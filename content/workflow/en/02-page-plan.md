# Page plan

Give one page a clear job.

## Entry requirement

Enter with a clear audience and question; an existing page can also be re-briefed here.

## Goal

Turn the need into a writable, testable brief without unnecessary overlap with existing pages.

## Concepts first

- Page format: tutorials support action, comparisons support choice, product pages explain an offer, and tools complete a task. Choose the format around the need.

- Internal links connect pages on your site. A URL is a page address. Canonical signals a preferred URL for equivalent content; it does not delete duplicates.

## Inputs

- A stage 1 opportunity card or an existing page’s audience, question, and evidence.

- Related existing URLs, site sections, and available source material.

## Actions

### 02.1 Decide whether to create or update

Check whether an existing page already serves the task. Consider updating it when the task is the same; use a new page for a distinct task and connect related pages. A keyword variation alone is not a new-page rationale. Record the decision; do not casually remove pages or change URLs.

Output: Create/update decision and target URL.

### 02.2 Define reader success

Write: “After this page, this reader can do this task.” List 3–5 essential questions in the order a reader would act. Put unrelated material in a backlog rather than writing an encyclopedia.

Output: Reader outcome, page format, working title, and outline.

### 02.3 Assign evidence and assets

Assign screenshots, demonstrations, data, experience, or primary sources to each section. Explain the practical value you will add. Remove or flag unsupported assertions. Plan one task-relevant next action, such as a checklist download.

Output: Section-to-evidence map and next-action plan.

### 02.4 Plan links and languages

Choose a relevant section or article that can link to the page and useful onward resources. For bilingual content, plan stable URLs and matching translations; language switching should preserve the current article. Validate needs separately in each language.

Output: Internal-link plan and, where relevant, locale URL pairs.

## Tools

- Notes/editor and current site navigation. Optional public-page extraction helps organize material but does not decide demand.

## Deliverables

- Page brief: audience, outcome, primary question, format, target URL, create/update rationale, title, outline, evidence, inbound link, next step, and acceptance criteria.

## Acceptance criteria

- Another writer could use the brief; every section has a purpose; related existing pages have been reviewed; bilingual scope is explicit.

## Stop conditions

- If the page does not connect to a real need, return to stage 1. For URL migrations or merges, prepare a separate redirect and traffic-risk plan rather than making blind changes.

## Next step

Take the brief and evidence list to stage 3.
